# WiFi Remote Input

通过同一 Wi-Fi，将 Mac 上输入的 Unicode 文本（包括中文）发送到 Android 普通输入框。无需 USB 调试、ADB、Root、辅助功能权限或云端中转。

当前 MVP 包含 Kotlin Android 输入法及加密接收服务、SwiftUI macOS 客户端、扫码配对、一次性验证码与持久设备密钥，设备名称、多手机切换与同步输入，以及 Enter、Backspace、方向键。Mac 默认在窗口内实时输入，中文选词确认后自动发送，也可切换整段发送。两端跟随系统浅色／深色外观；Mac 支持工作台与状态栏弹窗。鼠标和全局键盘捕获尚未实现。

## 构建

要求 macOS 13+、Xcode/Swift 5.9+；Android 10+（API 29，TLS 1.3）。Android 构建使用 JDK 17、SDK 35、AGP 8.9.2、Kotlin 2.1.20、Gradle 8.11.1。

```sh
# 如缺少 Android 开发环境（Apple Silicon Homebrew）
brew install openjdk@17
brew install --cask android-commandlinetools
export JAVA_HOME="$(brew --prefix openjdk@17)/libexec/openjdk.jdk/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
sdkmanager --sdk_root="$ANDROID_HOME" --licenses
sdkmanager --sdk_root="$ANDROID_HOME" 'platforms;android-35' 'build-tools;35.0.0'

# 项目根目录
./scripts/build-macos.sh
cd android
./gradlew assembleDebug testDebugUnitTest lintDebug
```

产物：

- `macos/build/WiFi Remote Input.app`：本地临时签名，无需 Apple 开发者账号。
- `android/app/build/outputs/apk/debug/app-debug.apk`：可直接安装的开发测试包，不是正式发布签名。

不要将 `local.properties`、构建输出或密钥提交到仓库。Gradle Wrapper 会首次下载固定版本；需要访问 Google Maven、Maven Central 和 Gradle 下载源。

## 小米 13 安装与首次使用

1. 将 APK 通过你信任的文件传输方式传到手机，用手机文件管理器打开安装；按系统提示仅为该文件来源允许安装。整个过程不需要开启开发者选项或 USB 调试。
2. 手机和 Mac 连接同一可信 Wi-Fi。访客网络/AP 隔离会阻止两端互连。
3. 打开 Android **WiFi Remote Input**，依次点击「启用输入法」「选择输入法」。在系统列表中启用并选中 WiFi Remote Input。系统可能提示输入法有读取输入的能力，这是 Android 对第三方输入法的标准提醒。
4. 点击「开启接收」，允许通知，待状态显示「接收已开启」后点击「显示配对二维码」。二维码直接显示在页面中，应用自动选择 Wi-Fi 地址。
5. 在 Mac 打开新版 `.app`，点击 **「扫码配对」**，首次使用允许摄像头访问。将手机二维码对准 Mac 摄像头，识别后自动连接；无需填写地址、证书指纹或验证码。画面只在本机处理，不保存、不上传。
6. 二维码两分钟有效，只能使用一次。过期、已使用或重新生成后，旧二维码无法配对；失败时在手机重新生成再扫。二维码包含临时授权凭据，请只扫描自己手机应用内显示的码。
7. 在手机打开备忘录并点击正文；保持 WiFi Remote Input 为当前输入法。在 Mac 的实时输入区输入 `你好，小米 13 👋`（中文确认选词后自动送达），确认手机显示完整中文及 emoji。
8. 测试 Enter、Backspace 和方向键。再点击手机上任意密码输入框（无需输入真实密码），确认 Mac 显示密码框拒绝并暂停，且手机内容未变。

Android 0.6.6 首页采用 B 方案的连接状态布局，跟随系统浅色／深色模式；仅在未就绪时显示输入法设置，二维码内嵌展示，收起后立即失效。首页不展示地址、证书、备用码或测试输入框。

Mac 0.6.4 起仅提供扫码配对，不再展示连接设置、地址、证书指纹或配对码输入。无摄像头时请连接摄像头；未授权时在系统设置中允许摄像头访问。已配对手机仍可直接重连，地址变化时重新扫码。

之后点击 Mac「连接」即可，地址、指纹和设备密钥会保留。手机地址改变时可以重新扫码。每台手机仍只配对一台 Mac，重新配对会撤销该手机的旧密钥；一台 Mac 可以保存并同时连接多台手机。手机「忘记电脑名称」使旧会话及后续认证失效，「暂停接收」关闭端口。Mac「我的手机」每项右侧的垃圾桶按钮会清除该手机的本机记录和 Keychain 密钥，再次连接需要扫码。

HyperOS 如在切换应用后中止接收服务，可在应用电池设置中允许其后台运行；保留前台通知。锁屏时拒绝输入。完成使用后可在输入法面板切回原输入法并停止接收。

## 设备名称与多手机（0.5.0）

两端更新到 0.5.0 后，配对和重连会交换名称。0.6.2 起，Mac 优先使用系统电脑名称，若为纯编号则回退到 MacBook Pro 等硬件名称；手机优先读取系统设备名称，缺失时用可读机型或品牌名称。Mac 默认自动命名，并保留旧版已保存的手动名称；手机可在 App 中点「改名」或「自动命名」。名称在下次连接时同步，手机显示已配对电脑名称和连接状态；Mac 侧栏显示手机名称和连接状态。名称只是显示信息，认证仍依赖独立设备密钥和证书指纹。旧配对无需重新生成密钥，重连即可补全名称。

- **添加手机**：侧栏「我的手机」旁点 `+`，扫描另一台手机二维码；每台手机独立保存地址、名称和 Keychain 密钥。同一证书重新扫码会更新原记录，不产生重复设备。
- **切换输入**：点侧栏手机名称，保持其他连接在线，但输入只发给当前手机。切换会暂停并丢弃尚未发送的输入；点击输入区继续。已经交给网络的请求可能在原手机完成，绝不会转投新手机。
- **同步输入**：开启「多机同步输入」，勾选接收手机，点「连接勾选的手机」，在每台手机选中普通输入框后点击 Mac 输入区。文字、Enter、Backspace、方向键分别按顺序送往所有勾选手机。改变勾选项会暂停；重启应用默认关闭同步输入。
- 同步时顶部明确显示接收对象；点击手机名称只切换该手机的输入框预览，勾选项才决定接收者。预览仍来自对应手机的真实输入框，不能代表其他手机的内容。
- 任一目标断线、密码框拒绝、锁屏或其他输入失败时暂停整组，不自动重试、不静默跳过失败手机。群发并非原子操作，也不保证同一时刻到达：部分手机可能已接受上一条输入，请逐台检查后继续。不同手机的光标、内容和 Enter 动作可能不同。
- 「我的手机」列表的垃圾桶按钮仅移除对应手机记录及本机密钥，其他手机不受影响。Android「撤销已配对 Mac」仍只作用于这台手机。

## 输入与窗口

- **实时输入（默认）**：点击输入区后打字。拼音候选阶段只在 Mac 本地处理，确认后的中文才发送；英文、粘贴的文本也自动发送。**0.6.0 起只有一个实时输入框**：显示手机聚焦框的实际文字，直接在同一框中输入、选中替换、删除或移动光标。中文候选阶段不会被回传内容打断。单机编辑核对手机内容与光标后才应用；手机内容或焦点已变化时拒绝过时修改、暂停并重新同步，避免旧画面覆盖新内容。多机同步仍按各手机自己的光标发送，当前框只展示所选手机，不跨手机复制整篇内容或选区。
- **输入框同步与编辑（两端需 0.6.0+）**：输入页面可见且有键盘焦点时约每 250ms 刷新；连续输入期间也会定期重新读取。它是快照，可能有短暂延迟。密码框、锁屏、无输入框、读取失败时清除旧显示。仅接受应用提供的完整文本，最多 2048 个 UTF-16 单位；应用不支持或内容过长时明确提示，不用发送记录或截断片段替代。文字仅存在内存，经已配对的加密连接传输，不保存到文件或日志。应用不支持读取时无法镜像，只能继续向手机发送文字和结构化键，不伪造手机内容。
- **整段发送**：先编辑文字，再点击发送或按 ⌘Return；发送后保留草稿，避免把尚未编辑完的段落送出。
- Enter、Backspace、方向键与文字按顺序发送。中文组合输入期间，这些键先用于本地选词和编辑；Enter 默认执行目标输入框的动作，支持自定义 actionId 和发送动作。输入区「回车」菜单可为当前手机保存“自动／发送／换行”；Shift+Enter 始终换行。发送模式请求应用执行发送，不模拟点击屏幕，也不保证应用确实发出消息。微信请在「我 → 设置 → 聊天」开启「回车键发送消息」（取决于版本是否提供此项）；若微信不响应标准输入法发送动作，仍需在手机点击发送。
- 按 Esc、切到其他窗口、打开扫码或切换小窗，会暂停实时输入并清空尚未发送的队列。恢复时点击输入框或「继续输入」；返回窗口且输入框仍持有焦点时恢复输入。恢复不再受上一条请求仍在途的条件阻塞。已经交给网络的请求可能完成，不会自动重试。
- 密码框、锁屏、无输入框或编辑器拒绝时暂停；先处理手机上的状态，再继续输入。输入过长或队列满时也暂停，内容不会自动补发。
- 点击 Mac 顶部状态栏的键盘／手机图标打开 **紧凑弹窗**；再次点击图标或点到外部会收起并暂停输入。工作台右上角「切换到状态栏」可隐藏工作台并打开弹窗，弹窗右上角「展开工作台」可返回完整界面。关闭工作台后仍可从状态栏打开；退出应用使用应用菜单中的「退出」或 ⌘Q。弹窗与工作台共用连接，扫码通过侧栏在工作台内切换，不使用弹窗。
- Mac 和 Android 自动跟随各自系统浅色／深色模式，不需要单独设置。

## 验证

```sh
# 从项目根目录运行 Swift ↔ Kotlin 实际 TLS/WebSocket 互通测试
./scripts/test.sh
```

测试包含协议错误、认证失败、未配对输入、验证码过期/单次使用/跨连接猜测上限、密钥撤销、消息大小与频率限制、所有密码框变体拒绝、Android InputConnection 中文提交和按键/编辑器动作，以及证书指纹不符拒绝。另覆盖 Mac 中文组合输入、顺序发送、拒绝／断线不重发、暂停丢弃队列及 Android 两种系统外观启动。

互通测试会在本机临时启动**与 Android 相同的接收服务代码**，由真正的 Swift URLSession 客户端配对、重新认证并发送中文和六种按键；仅使用本机回环，不接触手机。Robolectric 测试执行 Android IME 到 InputConnection 的调用。这些验证不能替代小米 13/HyperOS 的实际输入框验收，手机安装、输入法启用和最终中文显示需要在实机操作。

## 安全与范围

仅提供固定证书的 TLS 1.3 WebSocket；未认证不能输入。密码、可见密码、网页密码和数字密码框均拒绝远程文本及按键。输入框保护依赖目标应用正确声明 Android `inputType`；无法识别故意伪装成普通文本的密码控件。日志不记录输入内容、剪贴板、配对码或密钥。应用不请求辅助功能权限。

连接中断时不自动重发，以免重复输入；需检查手机后重连。扫码会自动导入完整证书指纹，无需手动填写。没有公网服务、自动发现或后台开机自启动。
